# 技术设计：处置仓库历史 SMTP 凭据

## 边界

本任务只改变用户端本地配置的版本控制方式。`web/web-app/src/main/resources/application.yml` 保留在本机但不再跟踪；仓库以 `application.example.yml` 表达配置结构。管理端配置及当前工作区中的无关审计报告改动不参与本任务。

## 当前树结构

- `.gitignore` 精确忽略 `/web/web-app/src/main/resources/application.yml`，避免误伤其他模块或示例文件。
- 通过从 Git 索引移除而不删除工作树文件的方式保留本机配置。
- `application.example.yml` 保留与本地配置相同的键结构，所有实际秘密改为明显的示例值或空值。
- README 要求新克隆先复制示例文件为 `application.yml`，再填写本机值。

## 历史清理流程

1. 完成当前树结构调整并提交，确保新 `HEAD` 只包含示例文件。
2. 从远端最新引用创建隔离的裸镜像，并额外复制一份只读备份作为回滚点。
3. 使用 `git-filter-repo --path web/web-app/src/main/resources/application.yml --invert-paths` 从所有目标历史中移除真实配置路径；不读取或传递秘密值。
4. 验证该路径在所有可达提交中不存在，并检查目标引用齐全。
5. 精确强推已盘点的分支和标签；不使用可能误删未知远端引用的无条件 `--mirror` 推送。
6. 重新拉取远端引用复验，并向现有克隆仓库提供重新克隆或强制同步说明。

## 兼容性与风险

- 所有被改写提交的 ID 都会变化，现有 PR、分支基线和本地克隆可能失效。
- 旧克隆、fork、缓存和制品不会因远端重写自动消失；本任务接受这一残留记录，因为用户确认其中的 SMTP 密码已经过期。
- 强推前若远端出现新提交，停止执行并重新生成镜像，避免覆盖并发工作。
- 回滚方式是在发现异常时，将隔离备份中的原始引用精确推回远端；回滚会恢复泄露历史，只用于仓库完整性救援。

## 不采用的方案

- 只忽略当前配置：无法清除历史。
- 只重写历史但继续跟踪真实配置：后续提交可能再次泄露。
- 直接在当前工作区执行 `filter-branch`：会影响未提交工作且更难可靠回滚。
- 拆分 JWT 或替换本地 Docker 凭据：不属于用户确认的风险模型。
