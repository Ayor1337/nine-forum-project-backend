# 实施计划：处置仓库历史 SMTP 凭据

## 变更边界

- 行为差距：真实用户端配置同时受 Git 跟踪并存在于历史；目标是本机保留真实文件、仓库只保留示例、历史移除真实路径。
- 实际位置：当前配置位于 `web/web-app/src/main/resources/application.yml`；版本控制入口位于 `.gitignore`、Git 索引与远端引用。
- 必要文件：`.gitignore`、`README.md`、`web/web-app/src/main/resources/application.example.yml` 及本任务记录；本地 `application.yml` 只保留、不提交。
- 明确不做：不修改 Docker、数据库、MinIO、RabbitMQ、JWT 或无关审计报告。

## 执行清单

1. 恢复本机用户端 `application.yml`，添加精确忽略规则，并从 Git 索引移除但不删除工作树文件。
2. 新建不含真实秘密的 `application.example.yml`，更新 README 复制与启动说明。
3. 验证本地文件被忽略、示例 YAML 可解析、示例结构覆盖本地配置键，并运行 web-app 模块测试。
4. 按 Trellis 提交门禁提交当前树改造，保持无关工作区文件未暂存。
5. 检查远端引用无并发更新；在临时目录创建最新裸镜像和独立备份。
6. 若环境缺少 `git-filter-repo`，经批准后在隔离环境安装，再从全部历史中移除真实配置路径。
7. 验证路径在重写后所有可达提交中不存在，并确认分支/标签集合完整。
8. 经最终强推确认后，精确强推目标分支与标签；重新抓取远端复验。
9. 保留备份位置直至用户确认仓库正常，记录重新克隆/强制同步说明并完成全范围质量检查。

## 验证命令类别

- Maven：`./mvnw.cmd -pl web/web-app -am test`。
- 当前树：`git check-ignore` 确认本地配置被忽略，`git ls-files` 确认只有示例受跟踪；输出不得包含配置值。
- Git 历史：对所有目标引用查询真实配置路径，期望为 `0`。
- 引用一致性：重写前后比较分支/标签名称集合，而非提交 ID。
- 远端复验：强推后重新 fetch 到新的临时验证仓库，再次执行零匹配扫描。

## 审核与回滚门禁

- 用户已确认历史中的 SMTP 密码过期，不再设置凭据轮换门禁。
- 远端引用与快照不一致时停止，不强推。
- 验证不为零或引用缺失时停止，并从备份重新开始。
- 强推属于不可逆协作变更，执行前再次展示精确目标引用和备份位置。
