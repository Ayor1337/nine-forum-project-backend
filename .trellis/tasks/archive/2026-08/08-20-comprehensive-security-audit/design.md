# 全面安全审计设计

## 审计边界

本任务是只读审计，不在发现问题后直接修改产品代码。审计对象为当前 `develope` 工作树及其必要 Git 历史、本机隔离运行环境和已声明依赖。线上系统、第三方服务和破坏性利用均不在范围内。

## 方法

采用“资产与入口枚举 → 静态数据流审查 → 自动化扫描 → 动态验证 → 交叉复核 → 报告”的顺序。自动化工具只产生线索；严重和高危发现必须回到源码、配置、测试及运行行为复核。

### 1. 资产与信任边界

建立以下边界清单：

- HTTP：`web-app` 与 `web-admin` 的控制器、SecurityFilterChain、过滤器及方法级授权。
- 身份：密码登录、JWT、登录会话、邮件验证、Passkey/WebAuthn。
- 实时通信：WebSocket 握手、STOMP CONNECT/SUBSCRIBE/SEND、消息目的地与用户绑定。
- 数据：DTO/校验 → Controller → Service → Mapper/XML → MySQL/Redis/Elasticsearch。
- 外部服务：RabbitMQ、MinIO、邮件、Elasticsearch、公开基础 URL。
- 运维：Docker Compose、初始化 SQL、默认端口、API 文档和构建供应链。

### 2. 静态审计

- 使用全仓搜索和逐文件调用链追踪核查秘密、鉴权、授权、输入验证、SQL、富文本、文件/对象操作、网络请求、日志和错误处理。
- 对用户端与管理端的平行实现做一致性比较，避免只审一个入口。
- 对关键资源执行所有权检查：账号、权限、积分、内容、举报、私信、图片资产和数据修复。
- 检查 Git 历史中的秘密时只报告类型、位置和轮换建议，不在报告中复制秘密值。

### 3. 自动化验证

- 运行根目录 `Maven Wrapper` 测试。
- 生成 Maven 依赖树；优先使用可用的公开漏洞数据库扫描器。若网络或工具不可用，明确记录限制并以官方安全公告/漏洞库进行版本核对。
- 使用本机可用的秘密扫描、静态分析和容器配置扫描工具；工具缺失不触发未经授权的全局安装，改用可复现的仓库内命令或人工检查。
- 扫描结果必须去重，并标记直接依赖、传递依赖、可达性和置信度。

### 4. 非破坏性动态验证

- 前置条件：保留已校验的 `nine_forum` 可移植逻辑备份，且备份目录被 Git 忽略。
- 只对 `localhost` 上的项目服务发起请求；禁止公网目标、密码爆破、批量写入和高负载测试。
- 优先验证无需业务数据写入的行为：未认证访问、无效/过期/伪造 JWT、错误方法、CORS 预检、安全响应头、文档端点及 WebSocket 未认证握手/连接。
- 需要认证身份或会写入业务数据的场景，优先通过现有 MockMvc/单元测试与源码数据流验证；除非另有明确授权，不创建、删除或修改真实业务记录。
- 每项动态测试记录目标、请求类别、预期、实际结果和时间，不记录完整令牌或隐私数据。

## 严重级别

- 严重：低门槛导致系统级控制、批量敏感数据泄露、可复用生产秘密或大范围账号接管。
- 高危：可实现垂直/水平越权、敏感数据访问、身份绕过、持久化注入或高影响业务篡改。
- 中危：需要额外前提但可造成实际安全影响，或关键纵深防御缺失。
- 低危：暴露面、加固缺口或有限信息泄露，单独利用影响较小。
- 信息：无直接漏洞但值得记录的配置、可观测性或流程改进。

最终优先级同时考虑可利用性、影响、暴露范围和现有补偿控制；不只依赖扫描器的原始 CVSS。

## 证据与报告格式

审计证据写入任务 `research/`，最终报告写入 `security-audit-report.md`。每个发现包含：

1. 编号、标题、严重级别、CWE/类别与置信度。
2. 受影响文件和精确行号，必要时补充跨层数据流。
3. 攻击前提、可观察复现方式、影响和现有补偿控制。
4. 最小修复建议、验证建议及是否需要秘密轮换/历史清理。

报告不得包含真实密码、令牌、私钥、完整个人数据或可直接滥用的凭据。

## 风险控制与回退

- 动态请求出现非预期写入、服务不稳定或数据变化时立即停止；不尝试自动恢复。
- 数据恢复只有在用户另行明确要求时执行，且恢复前再次确认目标数据库。
- 安全工具若要求上传源码或数据到外部服务则不使用。
- 备份文件只保留在本地忽略目录；任务归档前由用户决定保留位置和生命周期。
