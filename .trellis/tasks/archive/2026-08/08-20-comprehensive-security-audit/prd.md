# 全面安全审计

## 目标

对 NineForum 后端仓库执行可复现、证据驱动的安全审计，识别可能导致未授权访问、数据泄露、账号接管、注入、滥用或供应链风险的问题，并输出按严重级别排序、带代码位置与修复建议的审计报告。

## 背景与已确认事实

- 项目为 Java 17 / Spring Boot 3.5.5 多模块 Maven 后端，包含共享模块 `common`、`model`，以及可独立启动的用户端 `web-app` 和管理端 `web-admin`。
- 主要外部边界包括 HTTP API、JWT、Passkey/WebAuthn、WebSocket/STOMP、MySQL、Redis、RabbitMQ、MinIO、Elasticsearch 与邮件服务。
- 仓库已包含认证授权、控制器、服务、Mapper、配置及部分安全相关测试，可进行静态数据流与契约核查。
- 初步证据显示配置文件含硬编码凭据，管理端安全链存在全局放行配置；这些只作为待验证线索，最终结论必须追踪真实调用链、保护层与可利用条件。
- 当前没有已授权的线上目标或生产凭据；用户已授权对本机隔离环境执行非破坏性动态验证。

## 审计要求

### R1：秘密与配置安全

- 检查当前文件与必要的 Git 历史中是否泄露凭据、令牌、私钥或可复用秘密。
- 检查默认账号、弱密钥、调试/文档端点、CORS、CSRF、安全响应头、错误响应与生产配置外部化风险。

### R2：认证与会话安全

- 检查登录、登出、JWT 签发与验证、会话撤销、密码处理、邮件验证、Passkey/WebAuthn 和 WebSocket/STOMP 身份绑定。
- 检查令牌混用、过期/吊销绕过、用户枚举、重放与权限声明信任问题。

### R3：授权与业务边界

- 枚举用户端和管理端入口，核查 URL 规则、方法级授权、角色/权限映射、资源所有权及水平/垂直越权。
- 对资金/积分、内容管理、账号管理、举报、私信、文件资产和数据修复等高影响操作提高优先级。

### R4：输入、数据与注入安全

- 检查 DTO 验证、MyBatis SQL/XML 动态片段、JSON/富文本处理、日志注入、XSS 输出路径和批量/分页参数。
- 检查 SSRF、路径穿越、任意文件/对象操作、危险反序列化、命令执行及资源耗尽路径。

### R5：基础设施与供应链

- 检查 Maven 依赖树与公开漏洞数据；记录工具版本、数据源和检查时间，区分直接依赖与传递依赖。
- 检查 Docker、数据库初始化、消息队列、对象存储、搜索服务及开发默认配置的暴露风险。

### R6：验证与报告

- 运行现有自动化测试和适用的安全扫描；失败必须区分代码缺陷、环境缺失与工具限制。
- 每个有效发现至少包含：严重级别、CWE/类别、证据位置、攻击前提、影响、复现/数据流说明、修复建议和置信度。
- 对高危与严重发现进行二次代码验证，避免把内部可信数据误判为外部输入。
- 汇总未发现问题的检查面、未覆盖范围及残余风险，不把“未发现”表述为“绝对安全”。

## 范围

### 包含

- 仓库内的生产代码、配置、资源、SQL/Mapper、Docker/构建文件和相关 Git 历史。
- `common`、`model`、`web-app`、`web-admin` 的跨层安全数据流。
- 非破坏性的构建、测试、静态分析、依赖与秘密扫描。
- 针对本地隔离环境的非破坏性动态验证，包括 HTTP、JWT、CORS 和 WebSocket/STOMP 的关键安全行为。
- 动态验证开始前必须完成数据库逻辑备份、校验备份文件并确保其不会进入版本控制。

### 不包含

- 未经明确授权的公网/生产系统扫描、口令尝试、社会工程或第三方服务攻击。
- 会删除、篡改或批量生成业务数据的利用验证。
- 本任务内自动修复发现；修复应在报告确认后另行规划，避免审计与整改相互污染。

## 验收标准

- [x] 审计矩阵覆盖 R1–R6，并记录每项状态、证据与限制。
- [x] 根目录 Maven 测试完成，或明确记录无法完成的具体原因。
- [x] 依赖漏洞与秘密扫描完成，包含工具/数据源时间戳；离线限制不得被伪装为无漏洞。
- [x] 用户端、管理端、WebSocket 与关键业务操作的认证授权链均被核查。
- [x] 所有严重/高危结论经过调用链复核，并给出可操作修复建议。
- [x] 最终报告按严重程度排序，包含执行摘要、发现详情、已覆盖项、限制和整改优先级。
- [x] 审计过程不修改产品代码、不攻击未授权目标、不执行破坏性测试。
