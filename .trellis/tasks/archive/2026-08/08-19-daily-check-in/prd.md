# 每日签到获取信用点

## Goal

为已登录用户提供每日签到接口，使其在东京时间每日首次签到时获得 5 Credit，并能在既有余额和流水中看到该变动。

## 已确认事实

- 用户端 API 位于 `web/web-app`；该应用默认要求所有未列入公开白名单的接口已认证。
- 既有 `/api/credits/balance` 与 `/api/credits/transactions` 分别返回当前用户的余额与流水。
- Credit 账户余额及流水通过同一事务、账户行锁更新；现有交易类型为后台发放、后台扣减和购买。历史设计明确为变动类型预留签到扩展。
- 当前数据库没有签到记录或可用于保证每日仅一次奖励的唯一约束。

## Requirements

- 新增仅限当前登录用户调用的签到接口。
- 每日首次签到固定发放 5 Credit。
- “每日”固定按 `Asia/Tokyo` 自然日划分，不受部署服务器或数据库时区影响。
- 每名用户每日最多获得一次签到奖励；并发或重复请求不得重复增加余额或产生重复奖励流水。
- 同日重复调用返回统一业务失败消息“今日已签到”，且不改变余额和流水。
- 成功签到时，原子更新 Credit 余额并写入可识别为签到的流水。
- 延续项目的 `Result<T>` 响应和既有 Credit 查询接口的可见性。

## 暂不纳入范围

- 连续签到、补签、随机奖励、任务配置后台和签到历史页面。

## Acceptance Criteria

- [ ] 已登录用户当日首次调用接口后，余额增加 5 Credit，并新增一条签到类型流水。
- [ ] 同一用户在同一自然日的重复或并发调用仅产生一次奖励及一条流水。
- [ ] 同日重复调用返回项目统一的业务失败响应，消息为“今日已签到”，且余额和流水均不变。
- [ ] 未登录调用遵循现有认证失败响应。
- [ ] 次日可再次签到并获得一次奖励。
