# 查询最近签到用户

## Goal

为用户端提供签到展示所需的只读接口：展示最近完成签到的五位用户，并让当前已认证用户查询其东京业务日的签到状态。

## Requirements

- 新增一个无需分页的只读接口，最多返回五位最近签到的有效用户。
- 最近顺序以 `daily_check_in.create_time` 倒序确定；创建时间相同以 `check_in_id` 倒序保证稳定排序。
- 列表项返回账号 ID、用户名、昵称、头像及签到时间；已删除或禁用账号不应出现在结果中。
- 新增当前已认证用户的签到状态查询接口，按东京业务日期判断，返回布尔值；未签到或无签到记录时返回 `false`。
- 两个接口都复用现有 Credit Controller、Service 与 DailyCheckIn Mapper 分层，不改变签到写入、Credit 发放、数据库结构或既有路由。

## Acceptance Criteria

- [ ] 调用最近签到查询可得到按签到时间倒序排列的列表，数量不超过 5，统一封装在 `Result` 中。
- [ ] 列表查询忽略已删除或禁用的账号，并在不足五条记录时正常返回实际数量。
- [ ] 已认证用户调用签到状态查询，当天已签到返回 `true`，否则返回 `false`；判断使用 `Asia/Tokyo` 日期。
- [ ] 新增 Controller、Service 与 Mapper 的测试覆盖路由、当前用户 ID 传递、排序/限制与签到状态的真/假结果。

## 范围外

- 不修改签到奖励、幂等性与 Credit 流水逻辑。
- 不增加分页、历史签到日历、缓存或数据库迁移。

## 关键决策

- 两个接口归入既有 `/api/credits` 路由：`GET /recent-check-ins` 与 `GET /check-ins/status`。
- 最近签到列表使用新的用户端专属 VO，避免复用搜索语义的 `UserSearchVO`，并明确携带签到时间。
- 本任务为轻量任务，仅维护 `prd.md`。
